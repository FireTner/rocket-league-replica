# MESH_SETUP — arena collision meshes

Two sources of Soccar collision geometry can drive `Sim`'s arena. They are not
equivalent, and the difference is visible in code and in logs.

| | clean-room mesh (in-repo pipeline) | dumped mesh (user-supplied) |
|---|---|---|
| What it is | Our own triangle mesh generated from published dimensions | `RLArenaCollisionDumper` output from the real game |
| Legal status | MIT, ours, regenerated by `make meshgen` | Psyonix-owned; **runtime input only** |
| Committed? | No (`collision_meshes/` is gitignored) | No, never |
| RocketSim hash | **not** in the known set | matches one of RocketSim's 16 SOCCAR hashes |
| `Sim::meshMode()` | `kMeshCleanroom` | `kMeshDumped` |
| `arenaDescription()` | `cleanroom-mesh` | `dumped-mesh` |

Both make `Sim::usingRealSoccar()` true and hand walls, pads and containment to
RocketSim. Only a dumped mesh reproduces the *literal* arena; the clean-room mesh
is an approximation and **is never evidence of 1:1 geometry** (see the fidelity
ledger below).

## Layout and invocation

RocketSim looks for `<mesh_dir>/soccar/*.cmf` (upstream `COLLISION_MESH_BASE_PATH`
+ `GAMEMODE_STRS[SOCCAR]`, `third_party/RocketSim/src/RocketSim.cpp:72-92`). One
directory level *below* the mesh dir is a lowercase game-mode name.

```sh
# In-repo clean-room mesh (no external input needed):
make meshgen
./build/headless_sim --tape tools/tas/tapes/straight_boost_600.csv \
    --ticks 600 --dump /tmp/out.csv --meshdir collision_meshes --meshreport
./build/game --meshdir collision_meshes

# User-supplied dump (the 1:1 path):
./build/headless_sim ... --meshdir /path/to/dumps --meshreport
./build/game --meshdir /path/to/dumps
```

The equivalent settings key is `[arena] mesh_dir` in `config/settings.ini`
(`docs/INI_SCHEMA.md`). Precedence: `--meshdir` > `[arena] mesh_dir` >
RocketSim's built-in default `./collision_meshes/`.

**Loud failure.** If a mesh dir is given but no Soccar mesh loads, both binaries
print a `FATAL` line naming the expected `soccar/*.cmf` path and exit non-zero.
There is no silent fallback to the analytic arena.

**Once per process.** RocketSim's mesh registry is global and initialized once
(`RocketSim::Init`); the first `Sim::CreateSoccar()` decides the arena for every
later `Sim` in that process. This is documented at `InitRocketSimOnce` in
`src/sim/Sim.cpp`.

## Producing a dump (the 1:1 path)

The dump tool is [ZealanL/RLArenaCollisionDumper](https://github.com/ZealanL/RLArenaCollisionDumper)
(MIT tool, not a game asset). It copies Rocket League's main binary, pattern-scans
it for the Bullet world pointer, and serialises each collision mesh it finds.

### Linux / Heroic (Proton) — working procedure

The dumper is Windows-only and locates the game with `WTSEnumerateProcessesA`.
**Wine implements the `W` variant properly but leaves the `A` variant a stub**
that returns `TRUE` with `count = 0`, so out of the box the dumper always prints
"Can't find Rocket League" — under any prefix, launcher, or Wine build. A small
shim DLL fixes this. The whole thing is scripted:

```sh
# 1. Launch Rocket League from Heroic, and ENTER FREE PLAY (an arena must be loaded)
# 2. Then:
~/Games/Heroic/scripts/dump-collision-meshes.sh
```

That script:
1. downloads `RLArenaCollisionDumper.exe` (v1.0.0) into
   `~/Games/Heroic/Prefixes/Rocket League/pfx/drive_c/rlcollision/`;
2. builds and installs `wtsapi32.dll` there via `build-wtsapi-shim.sh`;
3. runs the dumper with the **Proton** wine binary against the game's
   `WINEPREFIX` (`<HeroicPrefix>/pfx`, not the Heroic prefix root) and
   `WINEDLLOVERRIDES="wtsapi32=n,b"` so the shim is picked up;
4. copies the resulting `collision_meshes/soccar/*.cmf` into this repo.

Three details that are easy to get wrong:

| Detail | Why |
|---|---|
| The shim **must** be named `wtsapi32.dll` and the override key must be `wtsapi32` | `WINEDLLOVERRIDES="wtsapi=n,b"` silently does nothing; the name must match the DLL |
| The prefix is `<HeroicPrefix>/pfx` | Heroic's prefix root is a wrapper; the game's Wine prefix is the `pfx/` subdirectory |
| Use the Proton wine binary, not host `/usr/bin/wine` | mixing Wine versions against one wineserver gives `recvtime: Socket operation on non-socket` |

`wtsapi_shim.c` is self-contained: no libc, no mingw, no Wine headers. It uses
only `HeapAlloc`, `WideCharToMultiByte` and `NtQuerySystemInformation`, so it
links against Wine's own PE import libraries with `clang --target=x86_64-w64-windows-gnu
-nostdlib`. Nothing about the process list is invented — it comes from the same
source Wine's own `WTSEnumerateProcessesExW` uses.

### Windows

Run the dumper with Rocket League in free play; output lands in
`./collision-meshes/`. Copy it to `<mesh_dir>/soccar/`.

### Verifying the dump

```sh
./build/headless_sim --tape tools/tas/tapes/straight_boost_600.csv \
    --ticks 100 --dump /tmp/x.csv --meshdir collision_meshes --meshreport
# expect: MESH mode=dumped-mesh shapes=16 tris=8020 verts=4468 hashMatched=1 pads=34
python3 tools/verify/mesh_gates.py     # expect 11 PASS, 0 FAIL
```

A standard Soccar arena yields **16 meshes** whose hashes all appear in
RocketSim's known set (`third_party/RocketSim/src/RocketSim.cpp:20-28`).
`hashMatched=1` is computed from the `.cmf` files themselves, because
`CollisionMeshFile::UpdateHash()` is **order-dependent over `tris`** and cannot
be reproduced from a loaded `btBvhTriangleMeshShape` (the BVH reorders and
deduplicates triangles).

**Legal note.** These `.cmf` files contain Psyonix-owned geometry. Keep them
outside the repository, never commit them, never redistribute them.
`.gitignore` already excludes `collision_meshes/`.

## Generating the clean-room mesh

```sh
build/make_soccar_mesh <out.cmf> [--ramp-seg N] [--ceil-seg N]
```

`tools/meshgen/make_soccar_mesh.cpp` emits `<int32 numTris><int32 numVerts>`
followed by triangle indices and vertices — the `CollisionMeshFile` layout
(`third_party/RocketSim/src/CollisionMeshFile/CollisionMeshFile.h:15-38`). It
also prints `tris`, `verts`, the RocketSim `UpdateHash()` value and a
`windingErrors` count, and exits non-zero if any face is wound outward.

Output is deterministic: fixed lattice, no RNG, no clock, no unordered
iteration. `make meshgen` reproduces a byte-identical file.

### What the mesh supplies, and what it must not

RocketSim's `Arena::_SetupArenaCollisionShapes()` **always** adds analytic
floor/ceiling/side-wall planes for SOCCAR (`Arena.cpp:1030-1062`: `z=0`,
`z=ARENA_HEIGHT`, `x=±ARENA_EXTENT_X`). The mesh therefore supplies only what
those planes cannot:

- the two back walls (`y = ±5120`) with the goal-mouth opening,
- the four 45° corner chamfers (`|x| + |y| = 8064`),
- the wall height profile: floor fillet → wall → ceiling fillet,
- the goal recess (side walls, back net, roof).

It deliberately **omits** side walls and the floor/ceiling, because duplicate
triangles there would fight the planes.

### Fidelity ledger (read before claiming geometry 1:1)

| Feature | Value used | Source | Status |
|---|---|---|---|
| Side wall / back wall | 4096 / 5120 | `RLConst.h:14-15` | exact |
| Ceiling | 2048 | `RLConst.h:16` | exact (wiki says 2044; see `docs/arena_deviation.md`) |
| Corner chamfer | `\|x\|+\|y\|=8064`, 45° | RLBot wiki | exact |
| Goal mouth | half-width 892.755, height 642.775, depth 880 | RLBot wiki | exact |
| Floor fillet radius | 256, **circular** | RLBot wiki: "Approximately 256 (**non-circular**)" | **approximation** |
| Ceiling fillet radius | 256, circular | rl-opus only | **UNVERIFIED** |
| Goal-recess side/roof | plain box | inferred | **UNVERIFIED** |
| Ramp subdivision | 8 / 6 segments | this tool | tessellation, not fidelity |

So: the clean-room mesh makes RocketSim's real mesh collision path executable
(Bullet BVH triangle mesh, internal-edge info, shape indices, pad grid) and gives
mesh-mode gates something to measure, but its ramps and goal box are not
bit-identical to the retail arena. Mesh-mode gate results on the clean-room mesh
are recorded as `cleanroom` evidence, not as 1:1 proof.
